## 1. 목표
- 연구과제·심의위원회 관리 업무를 웹 한 곳에서 입력·수정·조회
- 과제별 적용 규정 자동 판별, 단계별 기한과 이행 여부 자동 산정
- 원자료 엑셀 내려받기(표준 양식, 홈페이지 게시현황 양식, 국회요구자료 맞춤 양식)
- 동료와 공동 사용: 로그인, 권한 구분, 수정 이력 자동 기록
- 후임자가 바로 이해할 수 있는 화면과 문구

## 2. 기술 구성
- 프론트엔드: Vite + React + TypeScript
- 스타일: CSS Modules 또는 vanilla-extract (Tailwind 사용 안 함, 시안 토큰 그대로 적용)
- 데이터: Firebase Firestore
- 로그인: Firebase Authentication (Google 로그인 + 이메일 허용목록)
- 파일: Firebase Storage (과제별 근거 파일)
- 엑셀: ExcelJS (읽기·쓰기, 서식 유지)
- 배포: GitHub Actions → GitHub Pages
- 규칙 배포: firebase-tools (firestore.rules, storage.rules)
- 외부 CDN 사용 안 함 (글꼴 포함 전부 자체 포함)

## 3. GitHub · Firebase 연결 절차 (Claude Code가 안내하고 사용자가 수행)
[Firebase]
1) Firebase 콘솔에서 프로젝트 생성 (예: khepi-research-ledger)
2) Authentication 활성화 → Google 로그인 사용
3) Firestore 생성 → 리전 asia-northeast3(서울), 프로덕션 모드
4) Storage 생성 → 같은 리전
5) 프로젝트 설정 → 웹 앱 추가 → firebaseConfig 값 확인
6) Authentication → 승인된 도메인에 `<github계정>.github.io` 추가

[로컬]
- .env.local 에 아래 값 입력 (.env.example 제공)
  `VITE_FB_API_KEY, VITE_FB_AUTH_DOMAIN, VITE_FB_PROJECT_ID, VITE_FB_STORAGE_BUCKET, VITE_FB_MESSAGING_SENDER_ID, VITE_FB_APP_ID`
- `npm i -g firebase-tools` → `firebase login` → `firebase use <프로젝트ID>`
- `firebase deploy --only firestore:rules,storage`

[GitHub]
1) 저장소 생성 (비공개 권장)
2) Settings → Secrets and variables → Actions 에 위 VITE_FB_* 6개 등록
3) Settings → Pages → Source: GitHub Actions
4) .github/workflows/deploy.yml 작성: main 푸시 시 npm ci → npm run build → Pages 배포
5) vite.config.ts 의 base 를 '/<저장소이름>/' 로 설정

[최초 관리자 등록]
- Firestore 콘솔에서 config/access 문서 생성 `{ admins: ["본인이메일"], editors: [], viewers: [] }`
- 이후 사용자 추가는 앱의 관리 화면에서 처리

## 5. 적용 규정 판별 (domain/regimes.ts)
규정 원문을 대조한 결과, 기한·절차가 달라지는 구간은 5개.
2022.3.2.(제146호, 직제), 2025.4.1.(제201호, 직제), 2025.4.23.(제209호, 서식), 2025.12.9.(제219호, 연구윤리지침), 2026.3.3.(제221호, 서식3)은 기한 변경 없음.

| 키 | 라벨 | 규정번호 | 시행일 | 적용 기준 |
|---|---|---|---|---|
| R2019 | 2019년도 규정 | 제77호(제정) | 2019.04.18. | 연구시작일(협약일) |
| R2020 | 2020년도 규정 | 제107호 | 2020.08.12. | 연구시작일 |
| R2022 | 2022년도 규정 | 제153호(전부개정) | 2022.07.15. | 심의 승인일 (부칙: 시행일 이후 선정 과제부터) |
| R2023 | 2023년도 규정 | 제174호 | 2023.05.12. | 심의 승인일 (기한 산정은 R2022와 동일, 라벨만 구분) |
| R2025 | 2025년도 규정 | 제212호 | 2025.08.11. | 연구종료일 (적용례 없음, 개정일부터 시행) |

판별 순서
1) regimeOverride 가 있으면 그 값
2) type "C" 이면 판별 제외 (수탁: 발주처 계약조건, 제27조)
3) endDate >= 2025-08-11 → R2025
4) 심의 승인일 >= 2023-05-12 → R2023, >= 2022-07-15 → R2022
5) 그 외 startDate 기준: >= 2023-05-12 R2023, >= 2022-07-15 R2022, >= 2020-08-12 R2020, 그 전 R2019.
   startDate 없으면 심의 승인일로 대체, 둘 다 없으면 "판별 불가(연구기간 입력 필요)"
6) 심의명이 "심의X" 이면 심의 승인일 무시

심의 승인일 산출
- review.ym("YYYY.MM.") 우선, 없으면 review.no 앞 4자리(YYMM)로 산출 (예: 2103-10 → 2021.03.)
- 심의개최 목록의 개최연월과 매칭해 개최 시작일 사용
- 2022년 7월, 2023년 5월은 심의 미개최 → 월 단위로도 판별 오차 없음

화면 표기 (개조식)
- 적용 규정: 2025년도 규정 (제212호, 2025.8.11. 시행)
- 판단 근거: 연구종료일 2025.11.06. / 2025.8.11. 이후 종료 과제 해당
- 현행 엑셀 '연구관리규정(기준)' 값과 다르면 경고: "엑셀 표기 2022년도 규정 / 판단 기준 상이, 확인 필요"
  (R2023 vs 엑셀 2022년도는 "기한 산정 동일, 라벨만 상이")

구간별 기준 (규정 기준표 화면과 동일 데이터 사용)

## 8. 입력 규칙 (domain/fields.ts)
- 단일 날짜: 20211210 / 2021.12.10 / 21.12.10 / 2021-12-10 → 날짜 저장, 화면 표시 YYYY.MM.DD.
- 기간: 20250101-20251231 / 2025.1.1~2025.12.31 → "2025.01.01.~2025.12.31."
- 출생년월: 650506 입력 → 1965.05.06. 표시, 연령 자동 산정(기준일 표기). 쉼표 표시 금지
- 금액: 숫자만 저장, 화면에만 천 단위 쉼표 (금액 항목 외 쉼표 금지)
- 심의승인번호: "YYMM-NN" 문자열로 저장 (엑셀 날짜 변환 금지)
- O/X/해당없음 항목: 드롭다운(선택 / O / X / 해당없음)
  대상: 연구과제 평가결과서, 최종보고서, 최종보고서 제출 지연 신청, 계약공람, 연구과제 변경/통보,
  비공개요약서·최종보고서·연구결과 평가서·연구정보요약서·연구활용 결과보고서(공표 서류), 정책반영 여부, 학회지 게재 여부, 정당가입 여부
- 빈 칸 안내 문구(placeholder)
  - 공문·근거·보고: "(작성 필요) 예: 건강증진연구소-110(2025.10.10.)"
  - 날짜: "(작성 필요) 예: 20251010"
  - 기간: "(작성 필요) 예: 20250101-20251231"
  - 금액: "(작성 필요) 예: 50000000"
  - 사유·의견: "(작성 필요)"
- 자동계산 항목(적용 규정, 기한, 상태, 평균점수, 익명화 성명, 연령)은 수정 불가, "자동계산" 표시
- 저장 전 변경내역 서랍에서 항목별 되돌리기
- 과제 상세 항목 순서: 심의 → 진행 → 평가·결과물 → 공개 (최종보고서 제출 공문번호는 제출일 바로 앞)

## 11. 문구 규칙
